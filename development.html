    Development

    Run the library, Next.js website and independent Monoline documentation locally.

    Install

    Use Node.js 24.14 or newer and the repository’s pinned pnpm version.

    pnpm install --frozen-lockfile
pnpm build:lib

    Run the website

    pnpm dev

    The website runs at http://localhost:3006. Rebuild the library after editing widget source because the website consumes its emitted package exports.

    Run the documentation

    pnpm docs:dev

    Open http://localhost:4181/. Documentation is built by Monoline Docs independently of Next.js. The custom docs hostname serves from /. API props are extracted from component source before the documentation build. Restart docs development after changing widget prop declarations to refresh the table.

    Verify

    The workflow regression tests require Bash and jq on your PATH, matching the GitHub-hosted Ubuntu runner. Install them before running pnpm test locally.

    pnpm test
pnpm typecheck
pnpm build:lib
pnpm docs:build

    Do not commit docs/dist, package dist or website .next output. The website and documentation have separate deployment targets; docs output is never mounted into the Next.js application.

    SEO and deployment

    The website is deployed independently to https://askwidget.chitrankagnihotri.com. For Vercel, set the project Root Directory to website and enable source files outside the Root Directory. website/vercel.json builds the library before Next.js and does not build or deploy documentation.

    Set NEXT_PUBLIC_SITE_URL to that production origin; canonical URLs, social URLs, robots and the sitemap use the same value. Vercel previews emit noindex and disallow crawling. The sitemap omits modification dates until real page revision dates are available.

    Monoline Docs deploys to https://docs.askwidget.chitrankagnihotri.com/ on GitHub Pages. Its site, base and seo configuration control canonical URLs, social metadata, publisher identity and the sitemap. The root base also emits robots.txt. Both the CI deploy and local deploy command preserve the custom-domain CNAME.

    Run pnpm --filter ask-widget-website test:seo against a production build, or set TEST_BASE_URL to an existing local server to check its rendered metadata.

    Identity synchronization is explicit: run pnpm --filter ask-widget-website sync:identity to refresh the checked-in fallback, then review the result. Normal development and production builds do not rewrite that file from a remote response.

    build:lib verifies ESM and CommonJS public exports, SSR rendering and both stylesheet aliases after emitting the bundle. CommonJS output uses .cjs because the package is declared as an ES module.

    Package build tooling

    The library build uses Vite, the React plugin and generated TypeScript declarations. Its configuration lives in vite.config.lib.ts; React stays external to the bundle. CSS uses cascade layers and theme tokens. Test styling in the consumer website because a host application can still override widget styles. Build tools and transformation speed are not consumer runtime guarantees.

    Website and documentation theme

    The website and documentation share assets/theme.css. The palette follows the widget’s neutral zinc surfaces. Change semantic colors there to keep both sites consistent in light and dark mode. Website layout and component styling live in website/src/app/globals.css; the Docs site loads the shared stylesheet through docs/monoline-docs.yml. The published widget has its own theme and can be customized with its theme and colors props.

    The website declares Tailwind’s reset and UI layers before the widget layers in globals.css. Keep that order when changing stylesheet imports; host resets must not override the widget’s composer, buttons or message styles.

    The website uses Monoline UI for buttons, labeled inputs, segmented selections, navigation, footer, theme switching and separators. Keep workbench layout local to the website. Its code examples compose Monoline CodeBlock with explicit Prism highlighting and custom asynchronous clipboard feedback; do not enable Prism’s automatic DOM scanning before React hydration.

    Repository cleanup

    Run pnpm obliviate to select build output, dependencies, caches or lockfiles. Build and dependency cleanup covers the library, website and docs workspaces. Lockfile deletion is a separate, explicit choice because it resolves the dependency graph again on the next install. Do not clean output while its preview is running. The menu propagates failed commands as a nonzero exit status.

    Use pnpm git to prepare a release PR through GitHub Actions or inspect recent release runs. Publishing and recovery follow the maintenance guide.

    Website domain migration

    The production website uses https://askwidget.chitrankagnihotri.com. Keep both the new domain and ask-widget.chitrankagnihotri.com attached to the same Vercel project. The host-specific rule in website/vercel.json permanently redirects requests from the old hostname to the matching path on the new hostname. It does not redirect local development or Vercel preview hostnames.

    Set the production NEXT_PUBLIC_SITE_URL to the new origin and redeploy. Verify the new property and sitemap in Google Search Console. Keep the old hostname’s DNS and TLS working for existing links. The npm package and repository names remain ask-widget. Documentation uses its own custom hostname with / as its base; these settings are independent of the website hostname.

    Website analytics

    The website uses Cloudflare Web Analytics while hosting stays on Vercel. Set NEXT_PUBLIC_CLOUDFLARE_ANALYTICS_TOKEN in the Vercel project’s Production environment to the public beacon token for askwidget.chitrankagnihotri.com, then redeploy. No token is stored in source. A missing token disables the integration; an invalid token fails the production build with a configuration error.

    The script loads after hydration only in production. Local development and Vercel previews do not send analytics. The beacon measures traffic and Core Web Vitals; there is no separate Vercel Analytics, Speed Insights or Umami reporter. Keep Cloudflare’s automatic script injection off when using this manual integration to avoid duplicate beacons. The published widget does not include analytics.

    Documentation analytics and custom domain

    Create a separate Cloudflare Web Analytics site for docs.askwidget.chitrankagnihotri.com. Set its public beacon token as the GitHub Actions repository variable CLOUDFLARE_DOCS_ANALYTICS_TOKEN. The docs deployment passes it to CLOUDFLARE_WEB_ANALYTICS_TOKEN; it is not read from Vercel.

    The JavaScript config adapter loads the maintained YAML through Monoline Docs and adds the native script integration. It does not rewrite generated HTML. Builds without the variable contain no beacon; normal local development needs no token.

    Configure the custom domain in GitHub Pages before pointing its DNS CNAME to chitranklabs.github.io. Keep HTTPS enabled and verify old GitHub Pages home, deep links and Markdown export redirects after the switch. Do not attach the docs hostname to the Vercel website project.
